## Implemented and executed

The exact captured OpenClash0.48.002 overlay blocks ordinary binary/profile/package/UI mutation paths; managed frontend APIs refuse policy/restart/upgrade operations while preserving reads and configured group selection. Protected dnsmasq restore state and a persistent independent DNS forwarding guard prevent a stop from restoring ISP/WAN DNS.

Boot/readiness/DNS-only repair are common to native/Compose. The paired pilot includes syntax-before-mount checks, separate mode/validator state, bounded readiness, owned cleanup and an independent volatile procd watchdog. It begins cleanup at a 900-second monotonic deadline or after three bounded readiness failures. Actual elapsed cleanup must be measured on target.

Pinned procd **58eb263d5abe03f8c1280bdfa65a3b052614215d** requests asynchronous termination. The controller therefore waits for captured PID/start-time lifetimes to exit and procd registration to clear, rejects respawn and cancels timed-out stop-helper children before a mount/generation switch. [Official source](https://git.openwrt.org/?p=project/procd.git;a=blob;f=service/instance.c;hb=58eb263d5abe03f8c1280bdfa65a3b052614215d).

## Provenance, maintenance and limits

Artifacts are checked against expected numeric repo ID, source commit, workflow/ref, issuer, hosted runner, subject digest and architecture using retained bundles/trusted roots. This follows [GitHub offline verification](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/verify-attestations-offline) and [SLSA1.2 verification](https://slsa.dev/spec/v1.2/verifying-artifacts); neither proves correctness or a SLSA level. Same-runner duplicate builds are narrower than independent reproducibility. Upstream CoreDNS image identity is pinned but its publisher signature was not independently verified. The auxiliary scratch image is locally assembled around verified official files and the attested fork, not upstream-maintained or independently image-attested.

Both repositories have enabled security updates/alerts and actual Dependabot PRs. Daily source scans were manually exercised successfully; corrected upstream sync's hosted no-op passed. It never automatically merges/deploys. Thirty-seven inherited Mihomo test/go.mod alerts remain open, with artifact-specific SBOM/version disposition. The excluded legacy interop environment must not be enabled without remediation; no clean-repository claim.

The shared official CoreDNS1.14.7 binary uses Go1.26.6 and has residual advisory findings: 15 already-fixed CoreDNS version overreports and23 dependency/stdlib identities assessed against the narrow supplied configuration. That assessment is not a clean scan or exploit proof. Preserve it and prefer a tested official rebuild; enabling other plugins/transports reopens review. The common package/license inventory and Unbound/OpenSSL publisher fix-boundary review are recorded under evidence. Native and Compose inherit these same payload obligations; private images are not a complete public redistribution/notice bundle.

The independent monitor checks both repositories and replaces stale green state after checker failure. Two obsolete runs still have contradictory queued/cancellation API state, retained as a warning. No operator/channel/real delivery test or independent timer is accepted or installed. On automation failure, suspend promotion and investigate; a stale heartbeat does not kill healthy routing. Keep accepted offline cohorts, not stock/plaintext substitution. Human review must own conflicts, toolchains/dependencies/actions, advisories, trust stores, provider bootstrap, releases and target acceptance. [NIST SSDF1.1 PO.2/3/4,PS.1–3,PW.4/7/8,RV.1–3](https://csrc.nist.gov/pubs/sp/800/218/final) is guidance, not certification.

Target gates remain bounded and separately reviewed: R0 artifact/profile preflight≤10min; R1 isolated loopback semantic/API tests≤20min; R2 initial frontend conversion/rejected artifacts≤30min; R3 UI/API/update entry paths≤20min; R4 staged subscriptions≤20min; R5 crash/unhealthy/fail-closed≤30min; R6 offline missing-core≤20min; R7 exact package transaction≤45min; R8 cold reboot/time/bootstrap≤30min; R9 interruption/whole-generation rollback≤30min; R10 actual monitoring delivery≤15min plus36h observation. Each requires current hashes, local management/recovery, exact owned backup and stop on unexpected DNS/application/network/identity change. The current unmanaged baseline is the explicit initial rollback, with its known protection limits; later rollback uses accepted cohorts. No approval for one gate authorizes another.

The private workstation project maintains the complete two-router configuration deltas, ABBA resource/corpus/fault plan, standards matrix, current handoff and raw-failure locations. Public evidence hashes support continuity without publishing household secrets. Remaining decisions include runtime, transport coupling, managed restrictions, key/operator/channel and production rollout. Retire the patch only when supported official behavior passes equivalent semantics, application routing and lifecycle acceptance, or deliberately accept a different architecture. Container packaging does not remove fork obligations.
